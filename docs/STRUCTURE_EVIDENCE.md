# 机械结构证据边界 / Structure evidence boundary

## 先说结论

本项目目前对若干运算行为已经有可测试模型，但**并不知道每台历史机器的完整内部连接**。页面中的数字轮、进位箭头、曲柄、齿轮、控制路径和“信息流”图示，不能自动被理解为某一台机器的真实剖面图。

证据规则统一见 [`docs/EVIDENCE_POLICY.md`](EVIDENCE_POLICY.md)。本文件只说明“结构图应该怎样读”。

## 不再把四件事混成一个等级

看任何结构 claim 时先问两组问题。

### Claim type

| 标记 | 含义 | 例子 |
|---|---|---|
| **M** | 数学 / 计算事实 | `0099 + 1` 在十进制寄存器中需要跨两级高位变化 |
| **H** | 历史记录 | 某专利、手册、实物说明某机器具有某机构 |
| **R** | 工程复原 / 解释 | 根据图纸和实物建立的现代重建、emulator interpretation |
| **P** | 教学 / 反事实模型 | 本站 generic carry arrow、简化齿轮、hand-crank backprop |

### Historical evidence strength（只用于 H/R）

| 标记 | 含义 |
|---|---|
| **E1** | 实物、原始专利、原图、同时代手册/技术资料、直接测量 |
| **E2** | 有清楚证据链的博物馆/学术研究/权威复原 |
| **E3** | 可靠二手资料 |
| **E4** | 当前仍是推断、开放问题或证据不足 |

旧版页面里的 A–D 徽章可能暂时保留兼容，但不要继续把“数学上确定”“史料很强”“教学抽象”塞进同一条轴。

## 三个容易混淆的词

### 数字的表示

本站核心模型常把数字表示为 `0–9` 的离散软件状态；历史机器可能把它实现为：

- 轮的位置；
- 轴的角度；
- 有效齿/拨针数量；
- 累加器寄存轮；
- 按键行程；
- 其他机械状态。

软件状态是 M/P 层表达，不证明某一台历史机器唯一采用哪种物理表示。

### 进位

本站可以测试的是功能关系：个位从 `9` 回到 `0` 时，必要时更高位增加 `1`。

历史机器如何做到这一点则是 H/R 问题：可能涉及 sautoir、弹簧、棘爪、分阶段耦合、键驱动累加机构等。页面默认的 `carry →` 箭头只是 P 层“状态影响”，除非旁边给出明确的机器/来源/图号，否则不是实体连杆路线。

### 连接 / 信息流

`A → B` 在本站默认表示：

```text
A 的状态/操作影响 B
```

它不自动表示：

```text
A 与 B 两个实体零件直接啮合
```

对于 Analytical Engine、backprop 等信息流图尤其如此。现代术语也不能仅凭相似功能反推历史机器内部结构。

## 结构图的阅读顺序

看到一张机械图或状态图时，应该能回答：

1. **它在表达什么计算关系？**（M/P）
2. **是否声称对应某个历史机器？**（H/R）
3. **对应哪一型号/设计/修订？**
4. **来源是什么？** 实物、专利、手册、图纸、复原还是二手描述？
5. **来源直接证明了什么？**
6. **项目为了教学又简化了什么？**
7. **哪些结构仍未知？**

如果第 3–6 项答不出来，就不应该把图画得像 1:1 历史剖面。

## 视觉真实性不能升级证据

一个漂亮的 3D 齿轮、金属材质或精准动画并不会自动让 P 变成 H。

原则：

> **视觉越具体，来源也必须越具体。**

如果只有功能证据，就画功能图；如果只有教学模型，就明确写 P；如果来源足够支持到齿数、轮廓、时序，再逐步增加几何细节。

本项目宁可显示一个“未知 / 尚未核实”的区域，也不把猜测画成历史内部结构。
